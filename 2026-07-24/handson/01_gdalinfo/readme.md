# 01. データ構造の確認（gdalinfo）

外部サービスに投げる前に、まず自分の目でヘッダを読みます。

## 実行

```sh
gdalinfo -stats dem_src.tif
```

## 出力の読み方（確認チェックリスト）

出力例（抜粋）と、どこを見るか：

```
Driver: GTiff/GeoTIFF
Size is 4500, 3750                     <- ピクセルサイズ
Coordinate System is:
    GEOGCRS["JGD2011", ...             <- [1] CRS。地理座標か投影座標か
Pixel Size = (0.000111..., -0.000111...) <- [2] 解像度（地理座標なら「度」単位）
Band 1 Block=4500x1 Type=Float32       <- [3] データ型
  NoData Value=-9999                   <- [4] NoData値
  Minimum=1.230, Maximum=513.870       <- [5] 統計値（-statsで出る）
```

| # | 項目 | 判断すること |
|---|---|---|
| 1 | CRS | 次工程 `-s_srs` の指定値。EPSGコードを控える |
| 2 | 解像度 | 地理座標の場合、度からmへの換算感覚（緯度1秒が約30m）を持つ |
| 3 | データ型 | Float32なら標高値そのまま。Int16なら整数丸めに注意 |
| 4 | NoData | 海域・欠測部の値。後段の `-dstnodata` に引き継ぐ |
| 5 | 統計値 | 標高レンジが対象地域として妥当か。負の大きな値が混じっていたらNoData処理漏れの兆候 |

## 課題

1. 配布データのCRSのEPSGコードを特定してください
2. 標高の最小値・最大値は対象地域の実際の地形として妥当ですか
3. NoData値は何に設定されていますか（未設定の場合もあります。その場合の影響を考えてみてください）
