# ハンズオン② 講師用メモ

## ライブラリ構成（裏取り済み）

- ロケーションベースには3系統あり、**新ロケーションベース**（`gps-new-camera` /
  `gps-new-entity-place`）が推奨。AR.js 3.4.0 以降で利用でき、バグ修正と簡素化が入っている。
- **AR.js 3.4.7 は A-Frame 1.6.0 を要求**する（3.4.4 以下は A-Frame 1.0.4）。バージョンの組み合わせを崩さない。
- 配信URLは `raw.githack.com/AR-js-org/AR.js/3.4.7/aframe/build/aframe-ar.js`。
  `raw.githubusercontent.com` を直接 `<script>` に指定すると MIME 制限で実行されないため使わない。
- カメラは既定の look-controls を切り、`arjs-device-orientation-controls`（smoothing つき）に置き換えている。

## 事前準備

- HTTPS 配信（GitHub Pages）。ハンズオン①と同じ。`./02_ar/app/` のURLをQR等で配る。
- 当日の立ち位置で `app/observation_points.geojson` の base を実測GPSに合わせて再生成しておく。
  そうしないとオブジェクトが会場から数百m離れた位置に出て見えない。

## iOS 対応

- 開始ボタンのタップ内で `DeviceOrientationEvent.requestPermission()`（および DeviceMotionEvent）を呼んでいる。
  ページ読み込み時に自動で呼ぶと拒否されるため、ゲートを必ず通す。
- iOS の位置情報ARは不安定なことがある。うまくいかない場合の代替として、iOS 向けの修正を多く含む
  後継ライブラリ **LocAR.js**（A-Frame 対応あり）への差し替えを検討する。今回は資料量と実績から AR.js を採用している。

## 期待される表示

- 各観測ポイントに、NDVI で色分けしたブロックとラベル（名前・NDVI値）が立つ。
  水域（ため池、NDVI 負値）は青、畑地は黄寄り、林縁・水稲は緑。
- 圃場区画は半透明のブロックとして押し出し表示される。
- 端末を回すと、各オブジェクトが実際の方位の方向に見える。

## トラブルシュート

- **カメラは出るがオブジェクトが出ない**：GPS 未取得（屋内）か、base 座標が現在地とずれている。
  HUD の GPS 表示を確認する。Android は高精度位置情報を有効にする。
- **北がずれる／向きが合わない**：地磁気センサーの未キャリブレーション。端末を8の字に振る。
  端末固有のズレの可能性もある（AR.js/three.js の既知の制約）。
- **iOS で権限ダイアログが出ない**：HTTPS か、タップ内で呼べているか。Safari の設定を確認。
- **ライブラリが読めない**：`raw.githack` のバージョンURLを確認。当日は事前に一度読み込んでおく。

## 実装の限界（説明ポイント）

- ポリゴンは「重心に、範囲サイズで押し出したブロック」を置いている。厳密な地理的フットプリント
  （頂点ごとの形状）ではない。正確な footprint を描くには、`gps-new-camera` の `latLonToWorld()` で
  各頂点をワールド座標へ変換し、three.js のカスタムジオメトリを組む必要がある。次の一手として扱える。
- 位置情報ベースの精度は数メートル。cm 単位が要る用途では、スライドで触れた VPS（Immersal の Web SDK 等）
  やマーカーベースを検討する、という判断につなげる。
