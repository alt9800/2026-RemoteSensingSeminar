# 05.【補足】3D Gaussian Splatting（3DGS）を試す

本日のハンズオンでは扱いませんが、3DGSを「取得する・見る・編集する」までの入口をまとめておきます。この分野は動きが速いため、記述は2026年前半時点のものとして読んでください。

## 3DGSとは（要点のみ）

- 複数枚の写真から最適化（学習）される3Dシーン表現
- シーンを「位置・大きさ・向き・不透明度・視点依存の色を持つ楕円体（ガウシアン）」の集合で表す
- NeRFと同じ「写真からの3D復元」の系譜だが、明示的なプリミティブの集合であるためリアルタイム描画に向く
- 出力は通常の点群とは異なる独自形式で、CloudCompareで扱えるPLY/LASを直接得ることは現状では難しい。フォトグラメトリとは別のアプローチとして捉えるのが適切

点群との使い分けの目安：**「測る」なら点群、「見せる」なら3DGS**。

## 取得する：スマホアプリ・SaaS

学習には本来GPUが必要ですが、以下のサービスがその部分を肩代わりしてくれます。

| サービス | 特徴 |
|----------|------|
| Scaniverse | Splatモードを搭載。端末内で処理が完結する |
| Luma AI | 動画をアップロードするとクラウドで3DGS化。Web埋め込み可 |
| Polycam | 写真測量・LiDAR・3DGSを統合したアプリ |

Scaniverseでの手順の目安：

1. 新規データ作成でSplatモードを選択
2. 対象の周囲をゆっくり一周しながら撮影
3. 端末内で処理（数分）
4. エクスポート（PLY / SPZ等）

## 見る・編集する：SuperSplat

**SuperSplat**（PlayCanvas製・OSS）はブラウザで動く3DGSのビューア兼エディタです。

https://superspl.at/editor

- PLY等をドラッグアンドドロップで読み込み
- 不要なスプラットの選択・削除、切り抜きなどの編集が可能
- 編集後のエクスポートにも対応

点群におけるCloudCompareに近い立ち位置と考えると分かりやすいでしょう。スキャン時に写り込んだ周辺環境の掃除など、公開前の整形に使えます。

## フォーマットの現在地

3DGSのファイル形式は標準化の途上で、複数の形式が並立しています。

| 形式 | 由来・特徴 |
|------|-----------|
| PLY | 原論文実装の出力形式。球面調和係数まで含むため非常に大きい |
| .splat | コミュニティ発の簡易圧縮形式。位置・スケール・色・回転を量子化した固定長レコードの並び。Webビューアで広く使われる |
| .ksplat | Three.js系ビューア（GaussianSplats3D）の圧縮形式 |
| SPZ | Niantic（現Niantic Spatial）が公開した圧縮形式。PLY比でおよそ1/10。仕様とライブラリがOSS公開されている |
| glTF拡張 | Khronosでガウシアンスプラットを格納する拡張の策定が進行中 |

注目すべきはglTF拡張です。**glTFに載るということは、3D Tilesに載る**ということを意味します（3D Tiles 1.1のタイル中身はglTFのため）。つまり：

- 巨大な3DGSシーンをタイル分割してストリーミング配信できるようになる
- CesiumJSをはじめとする既存の3D Tilesエコシステムがそのまま使える
- 点群・建物モデル・3DGSを同じ基盤の上で重ねられる

CesiumJSでは3D Tilesにガウシアンスプラットを載せる取り組みが進められており、この合流が本命視されています。

## 現時点の実務的な整理

- フォーマット並立の過渡期であり、「点群にとってのPotreeConverter」に相当する定番変換ツールは確立途上
- 幾何精度が要らない「見せる」用途（観光・広報・現場の状況共有）から実用化が進む見込み
- 測量・点検など精度が必要な領域では点群が引き続き主役
- 状況は数年前のベクタータイル（MVT標準化前夜）に似ている。標準が固まる前でも「取得 → 変換 → 階層化 → 静的配信」という構図は共通しているため、本セミナーで学んだ考え方はそのまま応用できる
