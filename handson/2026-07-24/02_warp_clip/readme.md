# 02. 座標変換・クリップ・リサンプリング（gdalwarp）

WebメルカトルEPSG:3857へ変換しつつ、処理範囲を絞ります。

## なぜEPSG:3857にするのか

Webのタイルピラミッド（`{z}/{x}/{y}`）はEPSG:3857で定義されています。後段のタイル化ツールが内部で変換することもありますが、この段階で明示的に変換しておくとリサンプリング方法を自分で制御できます。

## 実行

```sh
gdalwarp \
  -s_srs EPSG:XXXX \
  -t_srs EPSG:3857 \
  -te <xmin> <ymin> <xmax> <ymax> -te_srs EPSG:3857 \
  -r bilinear \
  -dstnodata -9999 \
  dem_src.tif dem_3857.tif
```

- `EPSG:XXXX`：01で確認した配布データのCRS
- `-te` の値：配布資料の「対象範囲座標」を参照（講師配布のコマンド例をコピーしてかまいません）

## リサンプリング方法の選択（重要）

| `-r` | 用途 | DEMに使うと |
|---|---|---|
| `bilinear` | 連続値（標高・気温） | 適切。標準の選択 |
| `cubic` | 連続値・より滑らか | 可。エッジがやや甘くなる |
| `near` (nearest) | カテゴリ値（土地利用・分類コード） | 不適切。階段状の地形になる |

土地利用ラスターなど「値が分類コード」のデータでは逆にnearest以外を使ってはいけません。値の意味でリサンプリングを選ぶ、が原則です。

## 解像度を揃える

```sh
gdalwarp -tr 10 10 -r bilinear dem_3857.tif dem_10m.tif
```

- `-tr 10 10`：EPSG:3857での10m相当。元解像度より細かくしても情報は増えません

## 確認

```sh
gdalinfo -stats dem_10m.tif
```

- CRSがWebMercator（EPSG:3857）になっていること
- 標高の統計値が変換前と大きく変わっていないこと（大きく変わっていたらNoDataの混入を疑う）
